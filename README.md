# Geo3D

**高中立体几何的 3D 解题与演示**　·　v0.3.1

拍一张立体几何题的照片（或直接把题目文字打进去） → 认出题面 →
**在本地算出立体图形** → 给出分步解答 → 一个能转、能拖动点、能标角度的 3D 模型，
还可以打包成文件传给别的手机和电脑。

主要跑在安卓 14 以上的手机上（网页内核 + 打包成 App），目标用户就是一个人：我自己。

## 它跟别的拍照解题有什么不一样

**模型不算坐标，只描述关系；坐标由本地算出来，再逐条验回去。**

题目给 DeepSeek 之后，模型返回的不是「A 在 (0,0,0)、B 在 (2,0,0)」，而是「正方体 ABCD-A₁B₁C₁D₁，棱长 2，E 是 BC 上的动点」这样的约束描述。坐标由本地求解器迭代算出来，算完再逐条检查每条约束是否真的成立、每个面是否真的共面。

任何一条对不上就升推理档重做（high → max），两档都不过就如实说「建不出来」。

**宁拒不误：绝不展示一张可能错的图。** 这是整个项目的最高原则，其他一切设计都让位于它。

同样的规矩也用在数字上：**所有的度数、长度、比例都由本地算**，模型给的写法必须过一遍本地数值反验才采用。

## 已经能做的（一句话版）

拍照或打字进来 → 自动找出照片里的每一道题 → 可编辑题面 → 分步解题（辅助线逐条出现）→
3D 模型（转动、缩放可进入内部、单击面切显隐、点标注常驻）→
三类角度标注（含直角符号、角度制/弧度制、三档、**题目问的角重点突出**）→
长度与比例标注 → 元素清单（点一个元素，相关的一起亮）→
**动点手指直接拖、点驱动面实时变** → 自动存档与历史 → 余额查询。

细节见 [功能与特点.md](功能与特点.md)。

## 跑起来

```bash
pnpm install
pnpm dev            # 起开发服务器，手机访问 http://<电脑IP>:5173/
```

第一次用要在「设置」里填自己的 DeepSeek API Key（只存在手机本地，不进代码、不发第三方）。

不想拍照也可以：拍题页有一个「直接输入题目文字」的入口，直接打字就能建模。

## 自检

```bash
pnpm check
```

十三项，任何一项失败就非零退出：

| 自检 | 验什么 |
|---|---|
| geo | 内置示例图形的共面性与棱面归属 |
| solver | 约束求解器：各类约束与各类派生点 |
| text | 下标规范化、LaTeX 转可读数学符号 |
| scene | 场景解析与严格校验（认不得就报错） |
| history | 本地存档、配额降级 |
| solution | 解题过程解析、辅助元素合并 |
| demo | 内置示例端到端，含两个动点互不干扰、中位线定理 |
| drag | 拖点几何：射线到线段最近点、反解面内参数 |
| symbolic | 符号值解析与反验（√3/6、LaTeX 写法） |
| angle | 三类角的计算（用正方体的标准答案当靶子） |
| annotation | 把「要标哪个角」翻译成「图上画什么」 |
| elements | 元素清单的数据层（显示名、动点标记、与渲染层同一套 key） |
| tsc | 类型检查 |

要单独跑某一项，直接 `node src/xxx.check.ts`。

另有两条工具命令：

```bash
pnpm backup         # 备份到本地（完整仓库副本 + 历史快照）
node tools/phone-shot.mjs   # 取手机屏幕画面（手机侧不写任何文件）
```

```
src/

  solver.ts       约束求解器：LM 迭代 + 数值雅可比
  scene.ts        场景解析与校验、坐标 → 渲染结构
  solution.ts     解题过程解析、辅助元素合并、元素名解析
  symbolic.ts     符号值解析与反验
  angle.ts        三类角的计算 + 圆弧采样
  annotation.ts   角落到图上：顶点、方向、该补的辅助线、标签
  drag.ts         拖点几何
  history.ts      本地存档
  deepseek.ts     接口层（含 OCR 提问与解题提问）
  text.ts         文本规范化与 LaTeX 转换
  scene3d.ts      3D 渲染与手势
  main.ts         应用外壳
  demo.ts         内置示例题（免拍照测试用，同时是回归种子）
tools/
  backup.mjs      本地备份
  phone-shot.mjs  手机截图（手机侧零文件）
STATUS.md         项目唯一事实来源：决策、进度、铁律、边界
```

## 几条硬规矩

这些都是实际踩出来的，写在 `STATUS.md` 里：

1. **绝不用命令行工具改编含中文的源码**，只用编辑工具。踩过两次，文件直接损坏、只能重写。
2. **被 node 直接导入跑自检的模块，值导入必须写 `.ts` 后缀。**
3. **屏幕坐标换算一律用画布自己的矩形**，不能用窗口尺寸。渲染区被面板挤小后会整体偏移，表现为「手指按在点上却抓不住」。
4. **相机宽高比、画布尺寸、标注层尺寸三者必须一致**，否则点标注会和图形错位。
5. **两个控件不能占同一位置**，展开与折叠必须互斥。
6. **往 3D 页加东西前，先列一遍这一页从上到下有什么。**

## 手机接管（adb）的边界

开发过程中可以通过 adb 查看手机屏幕，用来自己验收界面。**边界是硬的**：

- 允许：取屏幕画面（手机侧不写任何文件）、点击本应用网页里的按钮
- 禁止：读写/列出/查找手机上任何文件，拷贝文件进出手机，查看通知短信通讯录剪贴板，装卸载应用
